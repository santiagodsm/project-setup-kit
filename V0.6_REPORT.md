## 2. Where the Claude Code docs differed from the prompt

Checked against code.claude.com/docs (hooks, permissions, settings, memory, output-styles, context-window pages), on 2026-10-24, Claude Code 2.1.310.

1. **A hook that times out does not block by default.** The docs say a timed-out or crashed PreToolUse hook lets the call through, unless the hook sets `"onFailure": "block"`. Your rule 6 wants the two guards to fail closed, so the write guard sets that field. The pre-commit is a git hook, not a Claude Code hook, so its state-file rule simply rejects.
2. **Deny rules use the space form** (`Bash(git push --force*)`); `:*` only works at the end. The docs also say deny rules "aren't a security boundary": `git -C . push --force` gets past them. I used several patterns per command (flag first, flag later), but you should treat them as stopping the usual mistake, not a determined workaround.
3. **A `Read` deny on `.env` also blocks Edit and Write on it.** So for an agent the permission rule stops a `.env` write before the hook even runs. Both layers are kept; the probe below tests each one alone.
4. **The state-file guard works at the tool level.** Hook input carries `agent_id` when the call comes from a subagent. So at the orchestrated tier the state file is protected twice: by the write guard (tool level) and by the pre-commit (commit level).
5. **CLAUDE.md is re-read after compaction anyway.** The docs say project-root CLAUDE.md is reloaded from disk after every compaction. The hook's "re-read CLAUDE.md" is harmless but redundant; the useful part is telling the agent to re-read the state file.
6. **Hook timeouts are in seconds** (minimum practical value 1). The guard and the after-compaction hook use 2.
7. Nothing else contradicted the prompt: `compact` is the right SessionStart source, exit code 2 blocks with stderr shown to Claude, and a SessionStart hook's plain output is added to Claude's context.

## 5. What I found about compaction signals

- **The docs describe no warning before automatic compaction.** Nothing says the model gets a system-reminder when context runs low. Claude Code compacts on its own when the conversation reaches a threshold. So the old stop rule ("stop when the context reminder appears") may never fire. That is why every stop rule now also covers compaction, and compaction means continue.
- **What the agent sees after compaction:** the earlier conversation replaced by a structured summary; project-root CLAUDE.md reloaded from disk; up to five recently used files re-read; invoked skills re-injected (large ones cut to fit, oldest dropped first); and the output of any SessionStart hook on the `compact` source. The new hook uses that last channel, and the probe above shows it arriving.
- There are also `PreCompact` and `PostCompact` hook events, and CLAUDE.md can carry a "Compact Instructions" section to steer what the summary keeps. I used neither; they are options if the one-line hook proves too weak.

**Output styles (7f), as a proposal only, not built.** Claude Code supports project output styles: a Markdown file in `.claude/output-styles/` selected by `"outputStyle"` in `.claude/settings.json`. A style changes the system prompt itself, which may hold up better over a long session than a section in CLAUDE.md. Two catches from the docs: a style "doesn't guarantee that something always happens", and a custom style drops Claude Code's built-in coding instructions unless its frontmatter sets `keep-coding-instructions: true`. Proposal: `harness-forge` could emit `.claude/output-styles/plain.md` from the same `COMMUNICATION.md` block with `keep-coding-instructions: true`, and set it in `settings.json`. Try it on one real build first, and only then decide whether to keep the CLAUDE.md section too, since both at once would be the duplication KD-021 forbids.

## 7. What I chose not to do, and other choices

- **Change 6 (AGENTS.md) skipped.** Your limit was that it touch only `project-brief`, `harness-forge`, `PLACEHOLDERS.md`, the two CLAUDE.md templates, `join-review` and `harness-doctor`. Moving the invariants out of CLAUDE.md would also have to change `build-loop` (it reads them from CLAUDE.md in its steps 3 and 7), the resident doctor template (its check 3 says invariants live in CLAUDE.md), both `MANIFEST.md` files, and `orchestrate-build`. The docs do confirm the premise: Claude Code reads AGENTS.md only when there is no CLAUDE.md, a CLAUDE.md can import it with `@AGENTS.md`, and this needs Claude Code 2.1.277 or later.
- **No instruction was dropped for the speed budget.** Nothing in the prompt needed a test run.
- **Extra safety I added:** the time limits inside the pre-commit hook (above).
- **`harness-forge` must commit the state file on its own, from the first commit.** I found this when the pre-commit hook rejected my own first testbed commit. It is now written into the forge step.
- **Deny patterns that may block an innocent command:** `Bash(git clean *)` also blocks a harmless `git clean -n` dry run, and `Bash(git commit * -n*)` would block a commit whose message contains " -n" (for example "add -n flag"). I judged both rare and cheap to work around.
- **`COMMUNICATION.md` uses `DESIGN.md` §2.1 literally** instead of `{{DESIGN}} {{GLOSSARY_SECTION}}`. Both values are fixed for every project (KD-004), and it keeps the canonical text readable by the setup chain, which runs before any placeholder is resolved.
- **Lint and typecheck commands still come from the build files.** `stack-decide` only got the format line you allowed; `harness-forge` derives the staged-lint command from the existing lint command.
- **The duplication check greps CLAUDE.md only.** The state-file template and `join-review` legitimately mention AMENDED blocks and drains, so grepping "outside the skill" everywhere would raise false findings.
- **The three new KD titles keep the " — " separator** because you wrote those titles that way and the other nineteen KDs use it. Every other line I added has no em dash.
- **KIT_DESIGN wording.** To meet your grep exactly, I also replaced plain uses of "full" outside History ("full tools" became "every tool", "reads beautifully" became "reads well"). The one remaining hit is KD-019's sentence saying it replaced the `standard` and `full` tiers.
- **Removed placeholders** `{{CODE_DIRS}}`, `{{LANGUAGE}}`, `{{FRAMEWORK}}`: nothing uses them after the CLAUDE.md rewrite.
