# Kit v0.6.1: report

**Done, and merged: `main` is now v0.6.1.** Every acceptance check passed. v0.6 is merged into `main` and pushed. v0.6.1 adds a guard that checks every shell command Claude runs, so the git and secrets rules now catch disguised spellings too, not only the obvious one.

## What changed

- `templates/enforcement/hooks/guard-bash.sh.tmpl` (new): runs before every shell command. It blocks force pushes, hard resets, skipped git hooks, destructive `git clean`, and shell writes to `.env` files or into `.git/`. It finds them anywhere in the command: after `&&` or `;`, inside `sh -c "..."` or `$( )`, and behind `git -C` or `git -c`.
- `templates/enforcement/settings.json.tmpl`: wires the guard on `Bash` with `timeout: 2` and `onFailure: "block"`, so a crash also blocks. One deny rule removed, see "Choices" below.
- `skills/harness-forge/SKILL.md`: emits the guard, lists it in `writes` and in the return, and states its speed rule.
- `skills/harness-doctor/SKILL.md` (check 14) and the resident doctor template: a missing or unwired guard is MAJOR; the speed-budget scan now names it.
- `skills/harness-migrate/SKILL.md`: migrated repos get the guard too.
- `KIT_DESIGN.md` KD-020: the sentence about deny rules being prefix patterns, so the guard matches the same operations.
- `.claude-plugin/plugin.json`: 0.6.1. `marketplace.json` has no version field.

## Choices and limits

- **The `-n` edge case is handled without weakening the rule.** The guard reads quoted text as one argument, so `-n` inside a commit message is never a flag. It blocks `-n` in a flag cluster up to the letter that takes the message (`-nm x` blocked, `-am "wip"` allowed), and a bare `-n` anywhere among the flags.
- **I removed one deny rule, `Bash(git commit * -n*)`.** It denied `git commit -m "fix -n flag parsing"` in the first must-allow run: a prefix pattern cannot tell a flag from message text. You asked to keep the deny rules, but this one made a must-allow check fail, and the guard covers the case correctly. `Bash(git commit -n*)` stays.
- **`.env.example.bak` is blocked.** Your rule exempts only names ending in `.env.example`; `.env.example.bak` matches `.env.*`.
- **Accepted false positives:** any command that merely mentions a blocked form is blocked, for example `echo git push -f` or a commit message containing the literal text `git reset --hard`. `cp .env backup` is blocked too, because the guard checks every file argument of `cp`/`mv`/`tee`/`install`, not just the target.
- **Not caught, because a string matcher cannot see them:** a path held in a variable (`f=.env; echo x > $f`), `eval`, a git alias defined earlier (`git config alias.p "push -f"`, then `git p`), and other languages writing files (`python -c "open('.env','w')"`). Those need a sandbox, which Claude Code's docs point to for a hard boundary.
- **If `jq` is missing**, the guard falls back to reading the raw input with `sed`, so it still checks rather than letting everything through.
