### 7. Worktrees for parallel units; re-enable the pre-commit type check (F7)

Claude Code's Agent tool has `isolation: "worktree"`; a worktree agent cannot write into the main checkout, which makes the single-writer rule mechanical. Measured on a 123-package TypeScript project: 0.02 s to create, 0.42 s to install, 1.44 s to check.

**What to build.**
- `templates/orchestrated/skills/orchestrate-build/SKILL.md.tmpl` Dispatch mechanics: a unit that will run alongside another is dispatched with `isolation: "worktree"`; U0 and any unit dispatched alone stay in the main tree. The brief tells a worktree unit to run the dependency install first (`{{INSTALL_COMMAND}}`, new placeholder, from STACK.md), commit on its branch, and report the branch name. The join merges each returned branch into the build branch (trees are disjoint by construction; a conflict is a BLOCKER for the join, recorded) before running the one full check, and then removes the worktree.
- `templates/enforcement/settings.json.tmpl`: add `"worktree": { "baseRef": "head" }` so unit branches start from the current build branch, not the default branch.
- `templates/enforcement/githooks/pre-commit.tmpl`: re-enable the type check at orchestrated tier (`PRECOMMIT_TYPECHECK` true) now that each parallel unit has its own tree.
